# Save Token — Context Optimization Rules

- **Multi-file, data & CLI tasks (3+ files, large logs/JSON/CSV):** Run inside `save_token_exec` (`state.<k>`, `tools.saveMemory`, ``await $`...`.compact()``, `tools.fetchText`, `intent`). Default `mode: "readonly"`; verify `dryRun: true` before `mode: "write"`.
- **Never raw-read large files (> 30 KB or > 200 lines):** Do not `read_file` whole monoliths; slice/filter via `save_token_exec` (`tools.grep`/`tools.read`) or `read_file` with `StartLine`/`EndLine` ≤ 150 lines.
- **CLI first & minimal browser ladder:** Run `git`, `gh`, `python`, `agent-browser` inside `save_token_exec`; browser order: `fetchText`/`search_web` -> `agent-browser` -> DevTools (no screenshots) -> `browser` subagent (`Model: "flash"`, `<2KB`).
- **Zero-LLM handoff & prior-chat recall:** Around ~60–100k+ tokens, call `save_token_handoff`. When asked to load prior chat context (`<id>`/`latest`), **NEVER** `read_file` `transcript*.jsonl`; call **`save_token_resume({ conversationId: "<id|prefix|latest>" })`** to auto-run 0-LLM `save_token_handoff` to `.md` and read it back (use `scripts/distill-chat.mjs --query "<keywords>"` only for deep lookup).
- **Minimal complete code (Ponytail):** Inspect related callers/tests before editing; pick the smallest complete change (reuse existing helpers/stdlib, delete over add, no unrequested wrappers/config/features). Fix bugs once at the shared root; mark deliberate limits with `shortcut: <limit>, <upgrade trigger>`.
- **Safety & self-check:** Never cut trust-boundary validation, data-loss error handling, or security; non-trivial new logic includes a small test/assert check. End replies with 1–2 lines: what was skipped/unchecked and any risk to know.
