# Save Token — Context Optimization Rules

- **Multi-file, data & CLI tasks (3+ files, large logs/JSON/CSV):** Run inside `save_token_exec` (`state.<k>`, `tools.saveMemory`, `tools.outline`/`tools.readSymbol`, ``await $`...`.compact()``, `tools.fetchText`, `intent`). Default `mode: "readonly"`; verify `dryRun: true` before `mode: "write"`.
- **Never raw-read large files (> 30 KB or > 200 lines):** Do not `read_file` whole monoliths; inspect symbols via `tools.outline`/`tools.readSymbol`, slice via `tools.grep`/`tools.read`, or `read_file` with `StartLine`/`EndLine` ≤ 150 lines (`PreToolUse` hook guards `read_file` & auto-compacts noisy CLI commands).
- **CLI first & minimal browser ladder:** Run `git`, `gh`, `python`, `agent-browser` inside `save_token_exec`; browser order: `fetchText`/`search_web` -> `agent-browser` -> DevTools (no screenshots) -> `browser` subagent (`Model: "flash"`, `<2KB`).
- **Zero-LLM handoff & scoped branch/tag recall:** Around ~70–80% context, save progress via `save_token_handoff({ branch, tags })` (`branch`/`tags` auto-inferred with 0 LLM tokens when omitted). When `SessionStart` injects `[Save Token External Cache]` or asked to resume (`<id>`/`latest`/`branch`), **NEVER** `read_file` `transcript*.jsonl`; call `save_token_resume({ branch })` (or `conversationId`) and query strictly inside scope via `save_token_search({ queries, branch, tags })` without scanning unrelated branches.
- **Minimal complete code (Ponytail):** Inspect related callers/tests before editing; pick the smallest complete change (reuse existing helpers/stdlib, delete over add, no unrequested wrappers/config/features). Fix bugs once at the shared root; mark deliberate limits with `shortcut: <limit>, <upgrade trigger>`.
- **Safety & self-check:** Never cut trust-boundary validation, data-loss error handling, or security; non-trivial new logic includes a small test/assert check. End replies with 1–2 lines: what was skipped/unchecked and any risk to know.
